# Промпт для агента: AI Calorie Tracker (PWA)

Скопіюй усе нижче і віддай коду-агенту (Claude Code / Cowork) як технічне завдання.

---

## Контекст і мета

Побудуй персональний веб-застосунок (PWA) для трекінгу калорій для 2-3 користувачів (не публічний продукт). Головна фіча — розпізнавання їжі по фото через AI. Має відкриватись і нормально працювати як на десктопі, так і на iPhone через "Додати на головний екран".

## Технологічний стек

- **Frontend:** Next.js (App Router) + React + TypeScript
- **Стилі:** Tailwind CSS
- **Backend:** Next.js API routes (serverless)
- **База даних:** Supabase (Postgres + Auth). Auth — просто email/password, без соцмереж, максимум на 3 акаунти
- **AI:** Google Gemini API, модель `gemini-2.5-flash` (безкоштовний тір, vision-підтримка). Ключ API зберігається на бекенді, ніколи не в клієнтському коді
- **PWA:** manifest.json + service worker для офлайн-кешу оболонки застосунку, підтримка "Add to Home Screen" на iOS 16.4+, Web Push для нагадувань

## Функціонал

### 1. Реєстрація і профіль (заповнюється один раз, редагується в налаштуваннях)
Поля: ім'я, вік, стать, вага (кг), зріст (см), рівень активності (сидячий/легка активність/помірна/висока), ціль (схуднення/підтримка/набір маси), швидкість цілі (повільно/стандартно/швидко), харчові обмеження/алергії (текстове поле, опційно).

При збереженні профілю — розрахувати денну норму калорій (формула Міффліна-Сан Жеора + коефіцієнт активності + дефіцит/профіцит під ціль) і БЖУ. Норму можна відредагувати вручну.

**Адаптація норми з часом:** раз на 7 днів фонова задача (cron / Supabase Edge Function) порівнює фактичну динаміку ваги користувача (якщо він її вносить) з очікуваною і за потреби пропонує (не застосовує автоматично!) скоригувати денну норму. Показати як банер-пропозицію в застосунку: "Схоже, твоя реальна динаміка відрізняється від плану — скоригувати норму до X ккал?" з кнопками Прийняти/Відхилити.

### 2. Сканер їжі (AI, головна фіча)
Два явних режими, юзер обирає перед фото (перемикач, не автовизначення):

**Режим "Страва":**
- Камера/завантаження фото готової їжі
- Фото → Gemini API з промптом розпізнати страву, оцінити вагу порції та КБЖУ
- Повернути AI-результат у структурованому JSON (назва, вага в г, ккал, білки, жири, вуглеводи, рівень впевненості)
- Показати юзеру картку з результатом і **обов'язково редаговані поля** (це не опція, а стандартний крок — AI на стравах помиляється на 10-30%)

**Режим "Етикетка":**
- Фото етикетки з КБЖУ на упаковці
- AI зчитує точні цифри на 100г/100мл із зображення
- Юзер вказує скільки грамів/мілілітрів з'їв → застосунок рахує підсумкові цифри
- Теж редаговані поля перед збереженням

Після підтвердження — запис додається до сьогоднішнього щоденника з мініатюрою фото.

### 3. Щоденник і головний екран
- Кільцевий/лінійний прогрес денної норми (з'їдено/лишилось), окремо по білках/жирах/вуглеводах
- Список прийомів їжі за день з мініатюрами, можливість видалити/відредагувати запис
- Швидкий ручний ввід їжі (без фото) як альтернатива
- Історія по днях і простий графік ваги/калорій за тиждень-місяць

### 4. Чат з AI-консультантом (stateless за задумом)
**Важливо:** чат НЕ передає в AI повну історію повідомлень. Замість цього кожен запит до AI збирає свіжий контекст з бази безпосередньо перед відправкою:
- Короткий профіль юзера (ціль, норма, обмеження) — з таблиці профілю
- Що з'їдено сьогодні і вчора (суми КБЖУ) — окремим SQL-запитом
- Останні кілька повідомлень з UI-переписки (2-4, лише для зв'язності тону відповіді, не для довгої пам'яті)
- Саме нове повідомлення юзера

Це збирається в system prompt при кожному виклику. Повна історія чату зберігається в БД тільки для відображення в UI (скрол назад), у запит до AI не потрапляє.

### 5. Нагадування
- Web Push нагадування: "залогуй сніданок/обід/вечерю", якщо за N годин нічого не додано
- Налаштування часу нагадувань у профілі
- Врахувати обмеження iOS: працює тільки після додавання PWA на головний екран

## Схема бази даних (орієнтовно, Supabase/Postgres)

```
users (Supabase Auth, стандартна)

profiles
  id, user_id, name, age, sex, weight_kg, height_cm,
  activity_level, goal, goal_pace, restrictions_text,
  daily_calories, daily_protein_g, daily_fat_g, daily_carbs_g,
  created_at, updated_at

weight_logs
  id, user_id, weight_kg, logged_at

food_entries
  id, user_id, source_type ('dish' | 'label' | 'manual'),
  name, photo_url, weight_g,
  calories, protein_g, fat_g, carbs_g,
  ai_confidence, logged_at

chat_messages
  id, user_id, role ('user' | 'assistant'), content, created_at

norm_adjustment_suggestions
  id, user_id, suggested_calories, reason, status ('pending'|'accepted'|'dismissed'), created_at
```

## Дизайн-напрямок

Мінімалістичний, з перемиканням темна/світла тема — **уникай буквального чорно-білого рішення**, обидві теми мають свій характер:
- Темна тема: глибокий насичений відтінок (не чистий чорний) — наприклад, темний чорнильно-графітовий з легким відтінком (не нейтральний сірий)
- Світла тема: тепла, не стерильно-біла основа
- Один акцентний колір, пов'язаний з темою їжі/природності (наприклад, приглушений шавлієво-зелений або теракотовий), використовується стримано — для прогрес-індикаторів, кнопок дії, активних станів
- Типографіка: чіткий контраст між великими цифрами (калорії, макроси — це "герой" екрану) і дрібним допоміжним текстом
- **Анімації — небагато, але доречні й функціональні, а не декоративні:**
  - Плавне заповнення прогрес-індикатора калорій при додаванні їжі
  - Легкий перехід/фейд при зміні теми
  - Мікро-анімація підтвердження при збереженні запису їжі (щось на кшталт короткого "чекмарку")
  - Уникати анімацій, що навантажують продуктивність на слабших пристроях — ніяких важких parallax/3D ефектів
- Дизайн має бути зручним для швидкого логування в один рух — це головний пріоритет UX перед візуальною складністю (див. приклад Cal AI: логування за 5-10 секунд)
- Респонсивність обов'язкова, з фокусом на мобільний viewport (це головний спосіб використання)
- Підтримка `prefers-reduced-motion`

## Пріоритет реалізації (у такому порядку)
1. Auth + профіль + розрахунок норми
2. Ручне логування їжі + щоденник + прогрес-бар
3. AI-сканер (режим "Страва")
4. AI-сканер (режим "Етикетка")
5. Чат з AI-консультантом (stateless контекст)
6. Адаптація норми (пропозиції раз на тиждень)
7. PWA-налаштування + push-нагадування
8. Тема (темна/світла) + фінальна поліровка анімацій
